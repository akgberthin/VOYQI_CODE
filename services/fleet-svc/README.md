# fleet-svc

Execution layer for the **VOYQI Fleet — Vehicle & Lifecycle Administration**
module (Section 6), FLT-001 through FLT-009. Port **8004**. VOYQI Fleet
owns every subscription vehicle — the dealership sells, the rental desk
rents, the fleet owns — and this service is the one source of truth
Mobility and Rental both read from by VIN.

## What's real here

**Genuine AI orchestration — the third specialist agent:**
- **FLT-003 Staging & Hub Allocation Board** — the **Fleet Intelligence
  Agent** (ai-orchestration-svc) reacts to `subscription.created`,
  `travel.activated`, and `vehicle.idle.48h` events by reading real hub
  supply (`get_hub_supply`) before recommending a transfer. Same
  two-layer discipline as the other two agents: a deterministic
  supply-shortage fallback that works with zero API key, and a live
  Claude tool-use path that reads actual context first. **Neither path
  ever dispatches a transfer** — `propose_transfer` only ever creates a
  `PROPOSED` order; a human fleet operator must separately assign a
  driver and dispatch. Moving a six-figure physical asset needs a human
  confirming logistics, the same non-negotiable principle as "never
  auto-send a message."
- **FLT-002 provisioning gate** — a vehicle cannot be staged, assigned,
  or added to the rental pool until `is_class_certified` is true, and
  certification itself requires the full provisioning chain (IoT device
  install, TLS client cert with **VIN as Common Name** — the platform's
  standing IoT security convention, card pairing) to be complete first.
  Software-defined assets need their software defined before they go
  near a member.
- **FLT-004 predictive maintenance** — alerts are generated by plain
  threshold checks (mileage since last service, DTC codes present),
  deterministic on purpose: pulling a member's active vehicle for
  maintenance is consequential enough that the trigger needs to be
  auditable arithmetic, not a model's judgment call. An URGENT alert's
  work order pulls the vehicle to MAINTENANCE status automatically.
- **FLT-005 Telematics & IoT Monitor** — geofence breach and device
  tamper events; a tamper event (`vehicle.tamper_detected`) always
  routes to the Compliance/Audit Agent — a real security signal on a
  high-value asset, not routine telemetry noise.
- **FLT-008 Incident, Damage & Claims** — declaring total loss
  (`incident.total_loss_declared`) always routes to the Compliance/Audit
  Agent: writing off a fleet asset is financially material enough to
  belong in the same audit trail as any other high-materiality action
  on the platform, the same principle as a legal-disclosure bypass or an
  expired-asset override elsewhere.
- **FLT-009 Fleet Financing & Floorplan** — pledging a vehicle beyond a
  facility's covenant utilization threshold is blocked outright above
  the credit limit, and flagged (`floorplan.covenant_breached`, always
  reviewed) when it crosses the covenant warning threshold below the
  hard limit — a real financial-risk signal reaching the same
  Compliance/Audit Agent that watches RBAC, marketing, and identity.

**Deterministic, honestly thinner AI tie-in:**
- **FLT-001** Fleet Inventory Master — VIN-level registry, search/filter
- **FLT-006** Depreciation & Asset Accounting — straight-line book value,
  market valuation tracking, pure arithmetic
- **FLT-007** Remarketing & Disposition — age/mileage eligibility
  thresholds, channel routing, recovery tracking
